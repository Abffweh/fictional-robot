# 实战复盘：《你的朋友，比你受欢迎》从 v1 到 v4

> 本文定位：一条真实制作过程里，用户（创作者本人）每一轮反馈改了什么、为什么改。
> 证据等级：**单个案例 + 一位创作者的判断**，不是平台数据，也没有 A/B 测试。可以当作检查清单的来源，不能当作"已被证明有效"的规律。
> 源码：`videos/friendship-paradox-3d/`（3D 黏土微缩风，三层渲染：3D 画面 / 文字 / 音效）。

## 速查：每轮反馈 → 规则

| 轮次 | 用户原话（摘要） | 落成的规则 |
|---|---|---|
| v1→v2 | "感觉像 PPT，要更多动效，节奏加快，前 3 秒吸引视线" | 画面不能是"字 + 图标"的幻灯片；每个镜头都要有东西在动；开场先上最强画面 |
| v2→v3 | "不能只有文字，要有绘图，风格要效仿；不做背景音乐，只有音效；最前面要举生活里真实遇到的情况" | 用具体场景（人物、道具、场景）讲，不用抽象图表开场；开头先给 2–3 个观众亲身经历过的瞬间 |
| v3 | "视频最开头要有『你的朋友比你更受欢迎？』这行字，要留住观众" | 第 0 秒就有一句问题式大标题，全片常驻顶部 |
| v3 | "这行字要从模糊到清晰淡入，起强调作用" | 标题逐字从模糊变清晰（约 0.06 秒一个字），出完再加一道下划线扫光 |
| v3→v4 | "别老用专业性的话，别说得那么精炼简短，要一看就明白，不用暂停思考" | 字幕宁可长一点，也要主谓宾完整、因果说全；术语换成大白话 |
| v4 | "可以保留公式，只是把长难句、省略句、专业词改通俗" | 画面上可以有公式（显得严谨），但字幕不能是公式的读法 |
| v4 | "不是要用大白话解释公式，只是把公式摆出来，你说你的，跟公式没关系" | 公式只当画面元素；字幕独立讲道理，不逐项解释符号 |

## 一、开头（0–13 秒）

最终方案：
1. **第 0.05 秒起**，顶部大标题「你的朋友比你更受欢迎？」逐字从模糊变清晰。问句里带"你"。
2. 同时，画面依次给出三个生活瞬间，每个约 3–4 秒：
   - 刷朋友圈，别人总在聚会；
   - 在群里说话，没人接茬；
   - 过个生日，人家的祝福刷了屏。
3. 第 4 句把感受说破：「你是不是也觉得：大家都比你受欢迎？」
4. 13 秒处才出片名卡。片名卡出现时，大标题暂时隐藏，避免两行标题打架。

为什么这样排：
- 标题问题负责"我为什么要看"，生活场景负责"这说的就是我"。两者同时出现，不用观众等。
- 左上角的检查单从这里开始累计"今日扎心 ×1/×2/×3"，让三个场景有递进感。

## 二、"说人话"改写：真实前后对照

v3 的字幕更短、更"精炼"，用户反馈看不懂、要停下来想。下面是同一位置 v3 → v4 的原句（取自 git 提交 `e7707f6`）：

| v3（被否） | v4（采用） | 改了什么 |
|---|---|---|
| 他翻出1961年的高中友谊调查， | 他拿1961年一群高中生的交友名单来算， | "友谊调查"是抽象名词 → 换成看得见的"交友名单"，并说出动作"拿来算" |
| 做个实验：8个人，10段友谊； | 我们来做个小实验：8个人，红线连着的就是朋友。 | "10段友谊"要观众自己换算 → 直接告诉他画面上红线是什么意思 |
| 牌子上，是每个人的朋友数。 | 每个人身后的牌子，写着他有几个朋友。 | 补全主谓宾，"朋友数"改成口语"有几个朋友" |
| 再看看：朋友们平均有几个朋友？ | 现在每人算一算：我的朋友们，平均有几个朋友？ | 改成第一人称视角，观众跟着算 |
| 8个人里，6个人的朋友比自己多。 | 8个人里，有6个人发现：朋友比自己更受欢迎。 | 加"发现"，把结论变成剧中人的体验 |
| 例外只有一个：中间的「社交达人」。 | 只有中间这位例外，他就是朋友最多的「社交达人」。 | 给标签加解释："朋友最多的" |
| 他有6个朋友，就出现在6份好友名单里； | 为什么？因为他有6个朋友，这6个人都会把他算进去； | 先抛"为什么"，再用"算进去"这个动作解释 |
| 越受欢迎，越常出现在「你的朋友」里。 | 朋友越多的人，就越容易出现在你的朋友名单里。 | "越…越…"省略了主语 → 补上"朋友越多的人" |
| 人均2.5个朋友，朋友的人均却有3.2个。 | 所以，大家平均只有2.5个朋友，／可大家的朋友，平均却有3.2个。 | 一句拆成两句；"朋友的人均"是绕口的省略结构 |
| 只要每个人的朋友数不一样多，／朋友的平均朋友数，就一定高于平均。 | 为什么会这样？说白了很简单：／人缘好的人，会出现在很多人的朋友名单里；／所以你数朋友时，数到的总是偏受欢迎的人。 | 原句是公式的文字版 → 改成观众能复述的因果链 |
| 放大到一千人的网络： | 换成一千个人，结果也一样： | 去掉"网络"这个术语，先给结论 |
| 2011年，研究者分析了7.21亿 Facebook 用户： | 2011年，有人统计了7亿多 Facebook 用户， | "7.21亿"→"7亿多"，精确数字对理解没帮助 |
| 2009年哈佛：随机找了319个学生， | 2009年流感季，哈佛的研究者随便找了319个学生， | 冒号省略句补全；"随机"→"随便"；交代"流感季"背景 |
| 结果，朋友组的流感，早来了约两周。 | 结果，被点名的这些朋友，早了大约两周得流感。 | "朋友组"是研究术语 → "被点名的这些朋友" |
| 想最早发现疫情？别挑人，挑「他的朋友」。 | 因为人缘好的人，接触的人多，总是最先被传染；／所以想早点发现疫情，多留意这些人缘好的人就行。 | 金句式的跳跃 → 补出中间的因果 |

可复用的改写规则：
1. **补全省略**：冒号句、"越…越…"、"X的人均"这类结构，补出主语和动词。
2. **抽象名词换成看得见的东西**：调查→名单，友谊→红线连着的人，组→被点名的这些人。
3. **术语换日常词**：随机→随便，网络→一千个人，人均→大家平均。
4. **一句只讲一件事**：两个数字比较，拆成两句。
5. **结论之前先抛"为什么"**：给观众一个等答案的理由。
6. **精确数字只在必要时保留**：7.21 亿 → 7 亿多；但 6/8、2.5、3.2 是片中现场算出来的，保留。

代价：
- 字幕变长后，同样内容从 96 秒拉到 111.4 秒（+16%）。用时间扭曲把画面放慢来对齐字幕，没有重拍。
- 单句最长到 22 字，超过了"一句 ≤ 20 字"的常见建议。这里选择了"一看就懂"优先于"短"。这是取舍，不是定论。

## 三、公式怎么处理

最终做法：黑板上原样写公式（μ + σ²/μ、符号说明、2.5 + 1.75 ÷ 2.5 = 3.2、"只要 σ² > 0 右边一定比 μ 大"）；同一时段字幕只讲"人缘好的人会被数很多次"。

我（制作方）当时提出的风险，供以后取舍：
- **好处**：公式让画面显得"有据可查"，懂的人会截图；不懂的人也不必看懂，字幕已经把道理讲完。
- **风险**：画面和字幕讲的不是同一件事，部分观众的视线会被公式吸走，漏掉字幕（多媒体学习里的"注意力分散"问题，详见 `language-and-sound.md`）。
- **折中**：把公式压暗、缩小，当背景板。成本是只重渲这 9 秒。

## 四、声音

用户明确要求：**不用背景音乐，只用音效**。最终是 103 个合成音效（弹出、打字、叮、印章、粉笔、人群、喷嚏等），加一层极轻的房间底噪，避免音效之间完全没声音。

这只是这一位创作者的风格选择，没有数据说明"无 BGM"更好或更差。两平台对 BGM 的一般做法见 `language-and-sound.md`。

## 五、留人装置

- **常驻问题标题**：全片顶部挂着「你的朋友比你更受欢迎？」。观众中途划进来，也知道这条在讲什么。
- **检查单 k/4**：左上角「看懂这件事 1/4…4/4」，四项依次是：你的感受 / 是真的吗 / 为什么 / 有什么用。让观众知道还剩多少、走到了哪一步。
- **右上角年代卡**：1991 / 1961 / 2011 / 2009，每次切到史料都换一张，提示"这是真事"。
- **数字现场计算**：8 人网络和 1000 人网络的数字由代码算出；如果和字幕不一致，渲染会直接报错，避免"图和字对不上"。
- **结尾回到开头场景**：三个开场场景里每个人头顶都冒出问号，再加一句「你觉得，你是图里的哪个点？评论区告诉我。」

## 六、制作效率（给下一条片子）

- **分层渲染**：3D 画面层（约 75 分钟）和文字层（约 10 分钟）分开渲染，再用 ffmpeg 叠加。只改字时，只重渲文字层。
- **时间扭曲**：字幕变长时，不改动画，只把"成片时间→故事时间"的映射拉长。
- **先出静帧再出整片**：每一版先抽 8–11 帧拼成一张联系表，人工过一遍，再给用户。
- **字幕检查脚本**：`scripts/script_lint.py` 能在渲染前查出句子太长、读不完、术语、长时间空档。v4 字幕的检查结果：0 个 ERROR；32 句里有 17 句超过每秒 5 字（5.2–6.8 字/秒），另有两句超过 20 字、一处 3.7 秒空档。
  - 每秒 5 字是调研里查到的"中文字幕常用标准"（见 `structure-by-duration.md` 6.1，证据是翻译字幕研究，未获独立佐证）。超过它通常读得完，但记得差。
  - 也就是说，v4 改成大白话、句子变长以后，阅读节奏偏快。下一条片子如果字数不变，画面要再放慢约 10–20%，或者只给重点句延长停留。

# 第 2 期：《为什么旁边的队，总比你快？》

> 源码：`videos/queue-paradox-3d/`。证据等级同上：单个案例 + 创作者本人的判断。

| 轮次 | 用户原话（摘要） | 落成的规则（已推广） |
|---|---|---|
| v1→v2 | "开头不够直观，第一个场景要明确配文：你排的这一列总比其他列慢" | 第一个场景的字幕直接说出现象，不只描述动作；画面给出可比较的进度（`hooks-first-seconds.md` 第十节） |
| v1→v2 | "列完例子之后加一句：这就是什么效应" | 例子之后用一句话给现象命名；名字要核实，没有学名就用可靠的近似说法（同上） |
| v2 | "不要提上一期视频怎么怎么样" | 每条片子自成一体，字幕不引用其他期（`language-and-sound.md` 1.6 ③） |
| v2 | "不要说『我们』这类带主观的词，可以说『用电脑模拟 1000 次』，不带主语" | 讲述动作用无主语陈述；对观众仍然说"你"（1.6 ②） |
| v2 | "『发现司机被超车的时间，比超车的时间长』要人想一下才懂；可以拆成几句，但别拿读者当傻子" | 不在一句里比较两个"……的……"；拆成 2–3 句、每句一个新信息，不解释常识（1.6 ①） |

**怎么防**：写完字幕先跑 `scripts/script_lint.py`，以上三类会报 WARN；再出声念一遍，凡是需要回头重读的句子都改掉。

# 选题讨论：《为什么盯着一个字看久了，就不认识了？》（语义饱和）

> 尚未成片；规则来自创作者在策划阶段的反馈。证据等级：单个案例 + 创作者本人的判断。

| 阶段 | 用户原话（摘要） | 落成的规则（已推广） |
|---|---|---|
| 策划 | "观众根本没有耐心看完 20 秒一个字，因为他们已经习惯了快节奏的短视频" | 互动环节不让观众干等：把需要时间的体验藏进多轮小游戏（任务 + 倒计时 + 揭晓），最后顺手问一句，再给视觉兜底；第 5 秒内开始互动，静止画面不超过约 2 秒（`structure-by-duration.md` 4.8；SKILL.md ④、铁律 7、冲突表） |

**怎么防**：写分镜时，把每个互动环节单独拿出来问一句——"这几秒里观众在做什么？"答不上来，就改成有任务的小游戏。
