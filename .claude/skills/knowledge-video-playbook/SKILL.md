# 抖音 / B站 知识视频策划手册

> **一句话**：先用这本手册定"做什么、怎么开头、多长、怎么说、怎么画、哪里有红线、发完看什么"，再交给制作流水线（例如本仓库的 `vibe-knowledge-video` skill，或 `videos/friendship-paradox-3d/` 的 3D 分层渲染）去做。

## 这本手册是怎么来的，能信多少

- 2026-10-13 用搜索引擎做了两轮调研，覆盖 9 个方向：平台机制、开头、结构、选题、画面、语言与声音、创作者案例、合规、互动复盘。每条结论都经过一轮对抗核查。限制：
  - 本环境打不开 bilibili.com、douyin.com 和多数中文站点，所有材料都来自搜索结果摘要，不是原文。
  - 平台后台的一手数据一条也没有。
- 每条结论都带标签：
  - [官方]：法规或平台官方资料
  - [研究]：学术研究
  - [财报]：上市公司财报
  - [第三方数据]：媒体或第三方统计、转述
  - [经验]：从业者经验
  - [案例]：案例观察
  - [推测]：推断
  - [经验·综合]：常识或综合判断，没有单一来源
  - 后缀"（低可信）""（未获独立佐证）""（未核查）"说明证据弱，引用前要看清。
- **最重要的三条底线**：
  1. 抖音、B站都**没有公开**任何"完播率 X% 进下一个流量池"一类的门槛。网上的"优秀线"互相矛盾，一律不用；复盘只和自己同时长段的作品比。
  2. 很多"黄金 3 秒"数据来自 TikTok / YouTube 的**广告研究**，研究的是广告，不是自然流量的知识视频。只借方向，不借数字。
  3. 本手册的规则是"有依据的默认做法"，不是保证。每条视频发完都要按 `engagement-and-distribution.md` 复盘，用自己的数据修正。

## 什么时候用

- 想做一条抖音 / B站知识视频，还没定选题、开头、时长、形式
- 稿子写好了，想检查开头抓不抓人、字幕读不读得懂、有没有合规风险
- 视频发出去了，想看数据、找问题段落
- 用户说"帮我想下一个视频做什么""这个开头行不行""为什么播放这么低"

不适用：纯娱乐、带货、直播；只要图文不要视频。

## 工作流程（每步对应一份参考文档）

```
① 定位 → ② 选题与角度 → ③ 开头 0–30 秒 → ④ 按时长排结构 → ⑤ 画面 → ⑥ 文案与声音 → ⑦ 合规 → ⑧ 发布与互动 → ⑨ 复盘
```

开工前复制 `assets/brief-template.md` 填一张策划单，空着的格子就是还没想清楚的地方。

### ① 定位：平台、时长、画幅、语言通道
- 时长按题的容量定，**不是越短越好**。推荐系统倾向于在同一时长组内比较 [研究]。
  - B站主力是横屏中长视频（参考 10–20 分钟）。
  - 抖音可以"横屏长版 + 竖屏切片"。
  - 抖音中视频计划要求横屏、≥1 分钟 [官方]（未获独立佐证）。
- 每条只定**一个**主要目标：看完、收藏、评论、关注，四选一。然后在结构里埋好对应的触发点。
- 参考 `references/platform-mechanics.md`、`structure-by-duration.md` 第一、二节。

### ② 选题与角度
- 先过六类自检：硬核、启发、干货、创意、传播、新知，至少占一项。
- 再用五维打分：受众面、好奇缺口、可视化难度、可信度、平台契合。可信度低于 3 分的不做。
- 每个题至少写 3 个候选标题。标题开头写用户会搜的完整问法（"为什么……""……是什么"）。
- 医疗、法律、财经、教育题，没有资质就只讲原理。
- 参考 `references/topics-and-angles.md`。

### ③ 开头：第 0 帧到第 30 秒
| 时段 | 要完成的事 |
|---|---|
| 第 0 帧 | 有字、有声、在动。删掉空白、logo、片头、"大家好" |
| 0–3 秒 | 说出核心名词、现象或问题（TikTok 广告研究：CTR 最高的一批约 63% 在前 3 秒突出了核心信息 [官方]，相关性数据） |
| 3–6 秒 | 钩住：悬念、反差、共鸣 |
| 5–15 秒 | 说清看完能得到什么、和"你"有什么关系，并先兑现一个小信息点 |
| 15–30 秒 | B站：交代背景和路线图；封面和标题承诺的第一个信息在 30 秒内出现 |

核心写法：**亮出结果或现象，藏住原因和机制**。这样"结果前置"和"保留悬念"可以同时成立。参考 `references/hooks-first-seconds.md`、`creator-cases.md`。

### ④ 结构：按时长档套模板
- 15–30 秒：只讲透一个点。
- 60–90 秒：一个承诺 + 3 个编号要点。
- 1–3 分钟：总分总，中点放一次反转。
- 3–5 分钟：开场 30 秒 + 2–4 章。
- B站 10–20 分钟：大约每 6 分钟一个单元，每个单元开头抛新问题。

中段的留人方法：
- 每个知识点先问后讲；
- 开放回路要关上；
- "常见误解 → 证据推翻 → 正确解释"；
- 快慢交替，不定死"几秒一切"。

互动环节（让观众亲自体验、猜、找）：
- 观众永远有事做：任何画面静止不超过约 2 秒；互动最迟在第 5 秒左右开始，不先铺垫再玩。
- 需要时间才会出现的体验（盯字、适应、饱和这类），不要让观众干等，把它藏进有任务、有倒计时、有揭晓的小游戏里（如"找不同"），每轮 5–8 秒，揭晓有音效反馈。
- 不承诺"你一定会怎样"，问"有没有一点怪？"；再给一个视觉替代画面，让没中招的人也能"秒懂"。
- 详见 `structure-by-duration.md` 4.8。

参考 `references/structure-by-duration.md`。

### ⑤ 画面
- 横屏主稿，竖版单独排版、单独渲染，不要给横屏原片加黑边。
- 把成片缩到手机实际大小，检查字能不能读清。
- 按信息单元换画面，不按秒数换。
- 只给"随时间变化"的内容做动画；其余用静态图加分步揭示（Höffler & Leutner d=0.37 [研究]）。
- 每个镜头只用一个强调手段（高亮、箭头、推近，三选一），字幕贴近它所指的图形。
- 遮住字幕只看画面，如果看不出在讲什么，就重做画面。
- 参考 `references/visual-design.md`。

### ⑥ 文案与声音
- **说人话**：
  - 主谓宾完整，不用省略句，因果说全；
  - 术语换成日常词，或者紧跟一句解释；
  - 一句只讲一件事；
  - 用"你"直接对观众说（个性化原则 d=0.30 [研究]）；但讲述动作不用"我们""我""咱们"，写成无主语的陈述（"用电脑模拟 1000 次"，不写"我们让电脑排了 1000 次"）。
  - 一句里不比较两个"……的……"（"被超车的时间，比超车的时间长"）：观众得停下来拆。拆成 2–3 句具体的话，每句只加一个新信息；也别拆过头，生活常识不解释，同一件事不换个说法再说一遍。
  - 每条片子自成一体：字幕里不提"上一期""上次说过"。系列关系放简介、合集、作者评论。
  - 本项目的真实改稿对照见 `production-lessons.md`。
- **字幕节奏**：每秒约 5 字，单行 ≤13–16 字，重点句放慢 [研究]（未获独立佐证）。
- **声音**：
  - 第 0 帧就要有声音，全片不留完全静音的空档。
  - 讲机制的段落不插梗、不加无关音效（诱人细节效应为负 [研究]）。
  - 成片要发两个平台的，不要把平台曲库的音乐烧进成片。
- **自动检查**：`python3 scripts/script_lint.py 字幕文件`，查读速、句长、术语、空档、开头。
- 参考 `references/language-and-sound.md`。

### ⑦ 合规
- **有 AI 成分就主动声明**。《人工智能生成合成内容标识办法》2025-09-01 起施行，第十条要求用户发布时主动声明 [官方]。
  - 抖音未标识的会被打上"疑似使用了AI生成技术"提示 [官方]。
  - 由 AI 写稿、写代码渲染出的片子，按 AI 生成合成内容处理 [推测]。
- 示意图和情景演绎要标注出来；每个事实都要能指出出处。
- 不用"看到最后有惊喜""点赞过万更新"这类话术。
- 字体用开源字体（如 SIL OFL 许可）。
- 参考 `references/compliance-and-risk.md`。

### ⑧ 发布与互动
- 标题、封面字、首屏字幕、简介里，都写用户会搜的完整问法。无旁白的片子没有语音可识别，画面字幕是视频里唯一可能被识别的文字。
- 结尾只问一个具体、一句话能答的问题（二选一 / 猜数字 / 对号入座）。
- 出处和勘误放哪里：
  - 抖音据报道已取消评论置顶，放在简介、片尾来源卡和作者自评论里；
  - B站用置顶评论。
- B站在"二选一"那一屏挂投票弹幕；全片最多出现一次关注或三连提示。
- 参考 `references/engagement-and-distribution.md`。

### ⑨ 复盘
- 读留存曲线：
  - 平直：不用改；
  - 缓降：改节奏或信息密度；
  - 陡降：记下秒数，对回那一秒的字幕和画面；
  - 尖峰：可能是重看，也可能是没看懂（YouTube 官方框架 [官方]）。
- 按时长分桶，只和自己同一时长段的作品比；下期只改一个变量。
- 复盘表模板见 `engagement-and-distribution.md` 7.4。

## 十条铁律（跨文档汇总）

1. 不写任何数字门槛，不把"流量池"当成官方机制。
2. 第 0 帧就有字、有声、在动；前 3 秒出现核心名词。
3. 亮出结果或现象，藏住原因和机制。
4. 标题、封面、开头说同一件事，正文必须兑现。
5. 时长由题的容量决定，复盘只在同一时长段里比。
6. 字幕说人话：句子完整、一句一事、术语有解释、每秒约 5 字；不用"我们"，不引用其他期，不让观众停下来拆句子。
7. 按信息单元换画面；动画只给真正"会变化"的东西；互动环节不让观众干等，用小游戏把等待变成任务。
8. 有 AI 成分就标；示意图和演绎要标；事实都有出处。
9. 结尾一句话结论加一个具体问题，讲完就停。
10. 每条都复盘，一次只改一个变量；自己的数据优先于本手册。

## 冲突与取舍（调研里互相打架的结论，已给处理办法）

| 冲突 | 处理 |
|---|---|
| "多路同步传达"vs Mayer 冗余原则 | 分场景：开头抢注意力时多路说同一件事；有口播加图示时不叠逐字字幕；纯字幕片不存在冗余问题，要防的是字幕和图抢视线 |
| 结果前置 vs 保留悬念 | 亮出结果或现象，藏住机制和原因 |
| 开头要不要铺垫 | 新号和抖音：不铺垫；成型系列可以有极短的固定开场，但不能挡在钩子前面 |
| 视频时长 | MOOC 研究的"6 分钟"衡量的是学习参与度，不是平台时长建议；按题的容量定 |
| 竖屏 / 开声 / 真人出镜 | 出自广告研究，不直接套用到横屏知识片 |
| 系列化 vs 每条自成一体 | 系列靠标题前缀、期号卡、合集、简介串起来；正片字幕不依赖、不提及其他期（多数观众是推荐来的新观众）[经验·综合] |
| 拆句说清 vs 别把观众当傻子 | 拆到每句只有一个新信息就停：最多 3 句；不解释常识，不同义重复；还说不清就让画面（计时器、对比条）承担 [经验·综合] |
| 体验需要时间 vs 观众没耐心 | 不缩短到无效，也不让人干等：把时长拆进多轮小游戏（任务 + 倒计时 + 揭晓），最后顺手问一句；再配一个视觉替代画面兜底 [经验·综合] |
| B站"播放分钟数" | 2023-08 只在后台内测；2024-05 据报道取消外显改版 [第三方数据] |

## 已知缺口（用之前知道这些没查到）

- 两个平台后台指标（2s 跳出率、5s 完播率、完播率、B站稿件分析）的官方定义原文。
- 头部创作者的逐字开场稿：打不开视频页，拿不到字幕。
- 无旁白纯字幕和口播在短视频平台上的留存对比：没有任何直接研究或数据。
- 《标识办法》和 GB 45438-2025 的条款原文：部分条号凭转述，用前对照原文。
- 发布时间、DOU+ / 起飞效果：没有可靠数据。

各文件末尾的"尚未解决的问题"一节列出了具体的检索词。网络放开后，可以按这些检索词补查。
